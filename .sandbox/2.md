## What you’re getting (right now)

**Architecture (MVP)**

* **Rust crate** (`crates/logler_core`) via **PyO3/maturin** exposing `line_matches_regex(line, pattern)`. This is a tiny, fast prefilter that proves the Rust pathway. We’ll move more hot path here later (highlighting, per-line parsing).
* **Python service** (`logler/`) with **FastAPI**:

  * `GET /health` trivial check.
  * `POST /search` hitting a **DuckDB** `events` table (substring or regex).
  * `WS /ws/log?path=...&regex=...&from_start=...` → streams tailed lines, minimal rotation handling (reopen on shrink), and ingests into DuckDB.
* **CLI** (`logler` via Typer): `serve` and `tail` (spawns server, opens UI).
* **React UI** (`ui/`): Vite + Tailwind + **react-window** for a smooth virtualized list. Connect panel lets you enter a path and optional regex; shows live log lines with timestamp + path.

**Quality-of-life**

* Clean **README** with a **10‑second quickstart** (dependencies aside).
* **CI** skeleton for Python tests, UI build, and a “best effort” maturin build step.
* **Tests**: one smoke test (`/health`), ready to grow.

## 10‑second quickstart (from the README)

```bash
# 1) Build optional Rust extension (Python fallback exists if you skip)
cd crates/logler_core
maturin develop

# 2) Install Python deps (uv shown; pip works too)
cd ../..
uv venv .venv && source .venv/bin/activate
uv pip install -r requirements.txt

# 3) Build the UI
cd ui && npm install && npm run build && cd ..

# 4) Run the server
python -m logler serve --port 8000
# open http://localhost:8000 (UI is served at /app/)
```

Dev mode? Run `python -m logler serve --no-static` then `cd ui && npm run dev`.

## What works vs. what’s a stub

**Works now**

* Live tail of a single file via WS with optional regex filter.
* Minimal rotation handling (reopen on truncation).
* Events ingested into DuckDB (`events(ts, file_id, path, line)`).
* `/search` API supports substring and regex (DuckDB `instr` / `regexp_matches`).
* Virtualized UI, smooth scrolling, simple header controls.

**Intentionally stubbed**

* Multi-log merged view & thread/correlation extraction (scaffold is ready; not wired).
* Parser zoo & timestamp normalization (basic arrival-time stamps only).
* Rich color rules/saved filters/bookmarks (UI wiring is straightforward; not implemented).
* Real Rust tailer loop (current tail is a portable, async Python poller; it’s the right seam to replace with Rust).

## Why this shape?

* You can **demo today**: live tail + fast UI + searchable history.
* The **hot path seam** is clear: replace the Python poller with a Rust tailer and push filters down, without reshaping the app.
* DuckDB gives you **vectorized scans** now and an easy onramp to FTS or n‑gram strategies later—while keeping everything local.
